# قالب تولید راهنمای تست ساده (PDF)

این سند **روش استاندارد تولید راهنمای تست برای اپراتور غیرفنی** را تعریف می‌کند.  
هر بستهٔ تست جدیدی که مخاطب آن کاربر بدون دانش فنی است و روی **سایت واقعی** تست می‌کند، باید از همین قالب پیروی کند.

---

## مرجع رسمی (الگو)

| مورد | مسیر |
|------|------|
| **خروجی نمونه** | `docs/راهنمای_تست_ساده_فرایندهای_حیاتی.pdf` |
| **اسکریپت تولید** | `scripts/generate_phase1_simple_test_pdf.py` |
| **دادهٔ مشترک** | `scripts/lib/process_test_guide_data.py` |
| **ابزار PDF فارسی** | `scripts/lib/pdf_fa_utils.py` |
| **فرم ثبت کمبود** | `docs/فرم_ثبت_کمبود_فرایندها.md` |

> **قانون پروژه:** قبل از ساخت راهنمای تست جدید، این فایل و اسکریپت الگو را بخوانید.  
> از ساخت قالب موازی (ساختار متفاوت، زبان فنی، localhost، seed) خودداری کنید.

---

## ۱. این قالب برای چه کسی است؟

| مخاطب | محیط تست | خروجی |
|--------|-----------|--------|
| اپراتور / تست‌کننده **بدون دانش فنی** | `https://lms.psychoanalysis.ir/` | PDF چاپی یا دیجیتال |
| بدون دسترسی به ترمینال، seed، یا localhost | مرورگر (Chrome / Edge) | یک فایل قابل ارسال |

**این قالب برای چه کسی نیست:**
- توسعه‌دهنده روی لوکال → از `docs/REBUILD_AND_TEST.md` استفاده شود
- تست فنی همهٔ مراحل با GAP-ID → `docs/راهنمای_جامع_تست_همه_فرایندها.pdf` و `scripts/generate_comprehensive_process_operator_test_pdf.py`
- بستهٔ markdown + Word → `docs/قالب_تولید_بسته_تست.md`

## ۲. ساختار PDF (الزامی)

هر راهنمای تست ساده **سه بخش** دارد:

```
┌─────────────────────────────────────┐
│  صفحهٔ جلد + مقدمه                  │
│  - عنوان، نام تست‌کننده، تاریخ      │
│  - آدرس سایت (ثابت)                 │
│  - چطور وارد شوم؟ (۴ قدم)           │
│  - روش تست (۴ قدم)                  │
│  - فهرست فرایندها (شماره‌دار)       │
│  - جدول همهٔ حساب‌های ورود          │
└─────────────────────────────────────┘
          ↓ (یک صفحه به ازای هر فرایند)
┌─────────────────────────────────────┐
│  تست N از M: [نام فارسی فرایند]     │
│  ۱. این فرایند چیست؟                │
│  ۲. ورود به سایت (آدرس+کاربری+رمز)  │
│  ۳. کجا بروید (مسیر منو)            │
│  ۴. چه کار کنید (لیست شماره‌دار)    │
│  ۵. باید چه ببینید                  │
│  ۶. اگر نشد: انتظار / دیدم          │
│  ۷. نتیجه: [ ] موفق  [ ] ناموفق     │
│  ۸. یادداشت (اختیاری)               │
└─────────────────────────────────────┘
          ↓
┌─────────────────────────────────────┐
│  صفحهٔ جمع‌بندی (جدول خلاصه)        │
└─────────────────────────────────────┘
```

### عناوین ثابت هر صفحهٔ فرایند

این عناوین را **عیناً** حفظ کنید تا همهٔ راهنماها یکدست باشند:

1. `این فرایند چیست؟`
2. `ورود به سایت:`
3. `کجا بروید:`
4. `چه کار کنید:`
5. `باید چه ببینید (نتیجه درست):`
6. `اگر نشد، بنویسید:`
7. `نتیجه تست:  [ ] موفق     [ ] ناموفق`
8. `یادداشت (اختیاری):`

| موضوع | نمونه |

### ممنوع در PDF تست‌کننده

| ممنوع | جایگزین |
|--------|---------|
| `localhost`، `127.0.0.1` | آدرس سایت واقعی |
| `python scripts/seed_...` | «اگر ورود نشد با پشتیبانی تماس بگیرید» |
| مسیر فنی `/panel/...` | نام منو به فارسی |
| کد فرایند `start_therapy` | نام فارسی «شروع درمان» |
| GAP-ID، process_code | فقط در فرم جداگانهٔ کمبود |
| اصطلاحات: bug، API، seed، mock | «مشکل»، «درگاه بانکی»، «شبیه‌سازی پرداخت» |

### آدرس و حساب‌ها

```python
SITE_URL = "https://lms.psychoanalysis.ir/"
DEFAULT_PASSWORD = "demo123"   # همهٔ حساب‌ها به‌جز admin
ADMIN_PASSWORD = "admin123"    # فقط admin
```

حساب‌ها از `DEMO_ACCOUNTS` در `process_test_guide_data.py` گرفته می‌شوند.  
در صفحهٔ جلد **جدول کامل** چاپ شود؛ در هر صفحهٔ فرایند فقط حساب همان تست.

## ۴. روش تولید بستهٔ تست جدید

### گام ۱ — تعریف محدوده

لیست فرایندها را مشخص کنید:

```python
# مثال: فاز ۲ یا یک موضوع خاص
MY_PHASE: list[tuple[str, str]] = [
    ("process_code", "یک جملهٔ ساده: این فرایند چرا مهم است؟"),
    ...
]
```

- `process_code` = کلید در `metadata/processes/`
- جملهٔ دوم = همان «این فرایند چیست؟» در PDF

### گام ۲ — کپی اسکریپت الگو

```bash
cp scripts/generate_phase1_simple_test_pdf.py scripts/generate_[slug]_simple_test_pdf.py
```

در اسکریپت جدید این موارد را عوض کنید:

| متغیر | توضیح |
|--------|--------|
| `OUT_PDF` | مسیر خروجی، مثلاً `docs/راهنمای_تست_ساده_[موضوع].pdf` |
| `PHASE_META` یا import لیست فرایندها | فرایندهای این بسته |
| `SIMPLE_STEPS_FALLBACK` | قدم‌های ساده به ازای هر `process_code` |
| `SIMPLE_EXPECT` | نتیجهٔ مورد انتظار به زبان ساده |
| `footer_label` در `GuidePDF(...)` | برچسب پاورقی PDF |

### گام ۳ — پر کردن قدم‌ها و انتظار

برای هر فرایند در `SIMPLE_STEPS_FALLBACK`:

1. حداکثر **۵–۶ قدم** — کوتاه و عملی
2. قدم اول: «در مرورگر بروید به [آدرس سایت]» (فقط در fallback؛ در جلد یک‌بار کافی است)
3. نام کاربری و رمز در قدم‌هایی که نقش عوض می‌شود
4. مسیر منو به فارسی، نه URL

برای `SIMPLE_EXPECT`: **یک جمله** — چیزی که تست‌کننده باید ببیند.

### گام ۴ — اولویت منبع قدم‌ها

در کلاس `SimplePhase1Builder` ترتیب `_simple_steps` این است:

1. `SIMPLE_STEPS_FALLBACK[code]` ← **ترجیح برای راهنمای ساده**
2. در غیر این صورت `enrichment["steps"]` (ممکن است فنی‌تر باشد)
3. در غیر این صورت `derive_ui_start(spec)` خودکار

> **توصیه:** برای راهنمای اپراتور، همیشه `SIMPLE_STEPS_FALLBACK` را پر کنید تا متن فنی enrichment وارد PDF نشود.

### گام ۵ — اجرا و بررسی

```bash
python scripts/generate_[slug]_simple_test_pdf.py
```

چک کنید:
- [ ] هیچ localhost یا seed در PDF نیست
- [ ] جدول حساب‌ها در جلد کامل است
- [ ] هر فرایند همان ۸ بخش ثابت را دارد
- [ ] صفحهٔ جمع‌بندی در انتها هست
- [ ] فونت فارسی درست نمایش داده می‌شود (Vazirmatn)

**مکمل:** `docs/راهنمای_عملیاتی_کامل_وب‌سایت_و_فرایندها_برای_آموزش.md` (بخش ۹)، `docs/student_lifecycle_ui_gaps_automation.md` (گام ۳.۱)

---

## هدف سند

این سند برای **اپراتور تست / QA / پذیرش مشتری** است تا بتواند:

1. محیط را آماده کند،
2. UI ساخته‌شده را گام‌به‌گام در وب امتحان کند،
3. صحت پیاده‌سازی را با معیار پذیرش مشخص تأیید یا رد کند.

> **توجه:** این فرایند صفحهٔ اختصاصی جدا (مثل آماده‌سازی ترم) ندارد؛ UI از الگوی عمومی `StudentQuestCard` + `TherapistPortal` استفاده می‌کند.

## ۲. پیش‌نیاز محیط

### ۲.۱ سرویس‌ها

- [ ] **PostgreSQL** در دسترس (`DATABASE_URL`)
- [ ] **API** (uvicorn) روی پورت **۸۰۰۰** (یا مطابق `VITE_PROXY_TARGET`)
- [ ] **admin-ui** (`npm run dev` روی **۵۱۷۳** یا build روی همان دامنه API)
- [ ] فرایندها seed شده باشند (`metadata/processes/start_therapy.json` در DB)

### ۲.۲ کاربران دمو (مرجع: `docs/WEBSITE_USERS_AND_ACCESS_FA.md`)

| نقش | نام کاربری نمونه | رمز | مسیر ورود |
|-----|------------------|-----|-----------|
| دانشجو | `student1` یا OTP موبایل | `demo123` / کد پیامکی | `/login` → تب دانشجو |
| درمانگر | `therapist1` | `demo123` | `/login` → ورود پرسنل |
| ادمین | `admin` | `admin123` | `/login` → ورود پرسنل |
| مالی | `finance1` | `demo123` | `/panel/finance` |

### ۲.۳ دادهٔ دانشجوی تست

دانشجوی تحت تست باید:

- [ ] رکورد `Student` داشته باشد (`term_count >= 1`)
- [ ] `course_type` = `introductory` یا `comprehensive`
- [ ] `therapy_started = false`
- [ ] فرایند ثبت‌نام دوره **بسته** باشد (یا مسیر اصلی روی `start_therapy` باشد)

**راه سریع:** تکمیل ثبت‌نام آشنایی تا `registration_complete` — سامانه معمولاً خودکار `start_therapy` را باز می‌کند.  
**مرجع تست خودکار:** `tests/e2e/test_student_admin_journey_registration_to_intro_completion.py`

## پیوست — ترتیب سریع برای دمو زنده (۱۵ دقیقه)
